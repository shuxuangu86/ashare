# Day 9 事件驱动回测

Day 9 建立最小但可审计的策略回测闭环：

```text
交易日开盘 → 处理此前订单 → 生成 Fill → 更新账本
           → 交易日收盘 → 记录权益 → 策略生成新订单
           → 下一交易日开盘才允许成交
```

## 时间边界

- 策略只在 `SessionCloseEvent` 收到当日完整日线和当时账户快照；
- 新订单的 `submitted_at` 等于信号日收盘；
- `NextOpenMatcher` 强制 `fill.occurred_at > order.submitted_at`；
- 因此用 T 日收盘产生的信号不能按 T 日收盘价成交；
- 市场 Session 必须严格递增且不能重叠，事件队列禁止时钟倒退。

## 订单和成交

回测订单与实盘 `OrderIntent` 相互独立。回测订单支持：

- `OPEN`、`PARTIALLY_FILLED`、`FILLED`、`CANCELLED`；
- 累计成交不得超过委托数量；
- Fill 必须匹配订单代码和方向；
- Fill ID 不得重复；
- 同一 `run_id` 和输入生成相同订单、Fill UUID 与结果哈希。

当前基线撮合使用下一交易日未复权开盘价。买单受可用现金限制，卖单受可用持仓限制。
若约束只能满足部分数量，订单保留为 `PARTIALLY_FILLED`。

## 会计账本

`PortfolioLedger` 的状态只由初始现金和不可变 Fill 产生：

- 买入：现金减少 `price × quantity + fee`；
- 买入费用计入平均持仓成本；
- 卖出：现金增加 `price × quantity - fee`；
- 已实现盈亏使用平均成本计算；
- 持仓不得为负，现金不足的成交被拒绝；
- 任意时点按收盘价生成现金、持仓市值和总权益快照；
- `PortfolioLedger.rebuild()` 重放 Fill 后必须得到相同状态哈希。

账本已经接受费用字段，但 Day 9 撮合器固定费用为零。手续费、印花税、滑点和冲击成本
将在 Day 10 通过版本化成本模型生成，不能在策略代码中硬编码。

## 验收

- 单元测试：事件队列、订单簿、Fill、会计和撮合器；
- 属性测试：现金、持仓始终等于成交推导值；
- 集成测试：因子 DSL → 订单 → 下一开盘成交 → 权益；
- Golden Test：固定三日市场的事件顺序、成交、权益曲线和最终状态哈希。
