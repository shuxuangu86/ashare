# ADR-0001：研究与执行进程隔离

- 状态：Accepted
- 日期：2026-07-16

## 决策

研究、数据、因子、回测和模型服务运行在 WSL2 / Docker。券商 SDK、交易回调和
执行代理运行在 Windows 原生进程。两者只通过经过认证、可审计的订单意图接口通信。

## 不变量

1. 策略只生成 `TargetPortfolio`，不持有券商连接。
2. 执行代理不运行因子、训练、优化、Notebook 或自由文本推理。
3. 每个 `OrderIntent` 具有稳定幂等键。
4. `UNKNOWN` 订单必须先向券商查询，不得直接重提。
5. 券商状态是实盘订单、成交、资金和持仓的最终来源。
6. Redis 只承载可重建的短期状态。

## 原因

券商 SDK 的 Windows 客户端依赖、生命周期和回调模型与研究环境不同。进程隔离可以
缩小故障域，限制研究依赖进入下单路径，并让执行代理实现独立的恢复和熔断策略。

## 后果

- 需要定义版本化的跨进程协议；
- 需要模拟 Broker 做 Linux / CI 测试；
- Windows 执行代理需要单独打包、日志和发布流程；
- 无法把 Docker Compose 一键启动等同于完整实盘系统启动。
