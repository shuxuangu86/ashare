# Tushare 5000 积分历史归档

## 一条命令

确认项目根目录 `.env` 包含 `TUSHARE_TOKEN` 和可信的 `TUSHARE_ENDPOINT` 后执行：

```bash
make tushare-backfill
```

命令默认归档 1990 年至运行当天的沪深 A 股研究数据。中断、断网或接口限流后，重新执行
同一命令即可从 SQLite 检查点继续，不会重复请求已经完整落盘的页面。

Tushare 的[积分频次说明](https://tushare.pro/document/1?doc_id=290)显示，5000 积分档常规
数据每分钟上限为 500 次且无每日总量上限。下载器默认单连接、最短间隔 0.15 秒，将理论
请求速率控制在约 400 次/分钟以内；真实速度通常由接口响应时间决定。

查看进度：

```bash
make tushare-status
```

## 下载优先级

1. 证券主表、名称变更、交易日历、公司与指数基础信息；
2. 未复权日线、复权因子、日频估值、停牌、涨跌停价格；
3. 利润表、资产负债表、现金流量表、财务指标和披露日期；
4. 基准指数行情、历史权重和申万行业成员；
5. 分红、限售股解禁、涨跌停榜与资金流扩展数据。

分钟、逐笔、实时行情、港股、美股、新闻和公告正文不属于本次范围；这些数据需要单独
权限，也不属于当前日频/低频 MVP 的必要输入。

## 数据安全和完整性

- 令牌只从 `.env` 或进程环境读取，不进入请求清单、日志或 Git；
- 每页供应商 JSON 原样写入 `data/raw/provider=tushare/`；
- 每页生成包含参数、响应时间、行数和 SHA-256 的 `manifest.json`；
- `artifacts/tushare-backfill/state.sqlite3` 保存断点；
- `artifacts/tushare-backfill/report.json` 保存最终或可恢复失败报告；
- 重复分页会立即报错，防止供应商忽略 offset 后产生无限循环或伪完整数据；
- 默认要求至少 20 GiB 可用空间，空间不足时在发起请求前停止。

下载期间不要启动第二个相同任务。进程锁会拒绝并行实例，避免超过频次或重复落盘。
